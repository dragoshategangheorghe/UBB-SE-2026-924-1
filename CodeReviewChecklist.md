# Code Review Checklist

Before approving a Pull Request (PR) and merging code into the main branch, the reviewer must verify the following items to ensure consistency and code quality.

## 1. Code Style and Conventions
- [ ] The code strictly follows the rules defined in `CodingStyle.md`.
- [ ] The code is readable, self-explanatory, and variables/methods are named clearly.

## 2. Architecture and Logic
- [ ] There is NO business logic in the UI (MVVM/API) or in the Data Access Layer (Repository).
- [ ] Links between domain objects are modeled through classes (e.g., a property of type `B` in class `A`), NOT just through an "IdOfB".
- [ ] Real functions are used instead of mock functions for the merged parts of the project (mocks are only kept for the other half of the project if needed).

## 3. Quality Assurance and Testing
- [ ] The code compiles successfully and runs without obvious errors.
- [ ] Unit tests have been written or updated for the new logic, and all tests pass successfully.
- [ ] Unfinished or buggy functionalities that prevent merging have been addressed.

## 4. Cleanup and Source Control
- [ ] Unused code, commented-out dead code, and duplicated database tables have been purged.
- [ ] Only source files have been included in the commit. NO files generated by the IDE (e.g., `bin`, `obj`, `.vs`) are included.
